# claude-heads-up: design

Date: 2026-10-09
Status: draft, waiting for review

## Problem

People who use Claude Code switch to YouTube, Instagram or Spotify while Claude works. When Claude finishes or asks for permission, they miss it, and Claude sits idle. SnapBack (github.com/teoobarca/snapback) solves this on macOS. Nothing comparable exists for Windows.

## Goal

A Claude Code plugin that gets the user's attention when Claude needs them, and gives it back when they reply:

- Alert: pause playing media, play a sound, focus the window that hosts the Claude session, show a toast, push to the phone.
- Resume: when the user replies in that session, play only the media that the alert paused.

Version 1 ships a working Windows backend. The code is structured so macOS and Linux backends can be added later without changing the core.

### Success criteria

- A stranger installs it with `/plugin marketplace add` and `/plugin install`, and it works with no config.
- A hook never blocks Claude, never prints to the conversation, and never fails the turn.
- Adding a platform means adding one folder under `internal/platform/` and nothing else.
- Unit tests for the core run on every OS in CI.

### Non-goals for version 1

- macOS and Linux backends (stubs only).
- Locking the phone (SnapBack's Android app).
- Codex CLI support.
- A settings UI.

## Decisions

| Decision | Choice | Reason |
|---|---|---|
| Packaging | Claude Code plugin | Hooks register on install; users never edit `settings.json`. |
| Core language | Go | Single static binary per OS, ~10 ms startup, trivial cross-compilation, stdlib covers HTTP/JSON/exec, easy for contributors to read. |
| Windows media control | Embedded PowerShell 5.1 script calling WinRT `GlobalSystemMediaTransportControlsSessionManager` | WinRT from Go is awkward; PowerShell 5.1 ships with every Windows 10/11 and can call WinRT directly. Runs detached so its ~1 s startup is invisible. |
| Config format | JSON | Go stdlib, no YAML dependency. |
| Third-party deps | `golang.org/x/sys` only | Win32 calls. Everything else is stdlib. |
| License | MIT | |

## Architecture

Two layers:

- **Core** (OS-independent): parses hook input, loads config, manages state, applies session and throttle rules, runs the steps in order, sends the ntfy push.
- **Platform backends**: one package per OS, selected by build tags, each implementing `platform.Platform`.

```
Claude Code hook ──stdin JSON──> bin/heads-up launcher ──> heads-up hook <alert|resume>
                                                               │
                                                     hookinput.Parse
                                                               │
                                                  engine.Alert / engine.Resume
                                     ┌──────────────┬──────────┴───────┬──────────────┐
                                  config        state.Store      platform.Platform   ntfy.Notifier
```

### Hook wiring (`hooks/hooks.json`)

| Claude Code event | Command | Notes |
|---|---|---|
| `Notification` | `heads-up hook alert` | Permission prompts and idle prompts. |
| `Stop` | `heads-up hook alert` | Claude finished its turn. |
| `UserPromptSubmit` | `heads-up hook resume` | User replied. |
| `PostToolUse` | `heads-up hook resume` | Covers "user approved a permission". Fires on every tool call, so resume returns immediately when no state exists for the session. |

Known gap (same as SnapBack): declining a permission fires no hook, so media stays paused until the user's next prompt.

### Platform interface

```go
package platform

var ErrUnsupported = errors.New("not supported on this platform")

type MediaSession struct {
    ID    string // backend-specific, e.g. Windows SourceAppUserModelId
    Title string // for logs only
}

type Platform interface {
    // HostWindow walks up the parent process chain from pid and returns the
    // first ancestor that owns a top-level window (terminal, editor, Claude app).
    HostWindow(pid int) (Window, error)
    IsForeground(w Window) (bool, error)
    Focus(w Window) error

    // PauseMedia pauses every session that is currently playing and returns
    // exactly those, so ResumeMedia never touches media the user paused.
    PauseMedia(ctx context.Context) ([]MediaSession, error)
    ResumeMedia(ctx context.Context, sessions []MediaSession) error

    PlaySound(path string) error
    Toast(title, body string) error
}
```

Each method may return `ErrUnsupported`; the engine treats that as "skip this step" and does not log it as an error.

### Alert flow

1. Parse stdin. Missing `session_id` → exit.
2. Load config. Event type disabled in `triggers` → exit.
3. Throttle: an alert for this session within `throttleSeconds` → exit.
4. Find the host window from the hook's parent process. If `skipWhenFocused` and the host window is foreground → exit.
5. Run the enabled steps in order; each step is independent:
   1. Pause media. If anything was paused, write a state record owned by this session.
   2. Play sound.
   3. Focus host window.
   4. Toast: title `Claude Code`, body `<project folder name>: <reason>` (reason is the Notification `message`, or "finished" for Stop).
   5. ntfy push with the same title and body.

### Resume flow

1. Parse stdin.
2. Read state. No record, or record owned by another session → exit. This is the fast path for `PostToolUse`.
3. Resume the recorded media sessions. Delete the record.

### Windows backend

- `HostWindow`: walk parents with `CreateToolhelp32Snapshot`; first process with a visible top-level window (`EnumWindows` + `GetWindowThreadProcessId`) wins. Handles Windows Terminal, VS Code, Cursor and the Claude desktop app without configuration.
- `IsForeground`: `GetForegroundWindow` compared with the host window.
- `Focus`: `SetForegroundWindow`, with the standard workaround for the foreground lock (synthetic Alt key press, falling back to `AttachThreadInput`). Restores minimized windows with `ShowWindow(SW_RESTORE)`.
- `PauseMedia` / `ResumeMedia`: `media.ps1` embedded with `go:embed`, written to the cache dir on first use, run with `powershell.exe -NoProfile -NonInteractive -WindowStyle Hidden`. Pause lists sessions with playback status `Playing`, pauses them, prints their IDs as JSON. Resume plays the given IDs. Resume runs detached so `UserPromptSubmit` is not delayed.
- `PlaySound`: `PlaySoundW` with `SND_ASYNC` on a `.wav`.
- `Toast`: WinRT toast through the same PowerShell helper, detached.

Dependency rule: `engine` imports interfaces only (`platform.Platform`, `Notifier`, `state.Store`, a `Clock`). No package outside `internal/platform/<os>` contains OS-specific code.

## Config

Path: `os.UserConfigDir()/claude-heads-up/config.json` (`%APPDATA%\claude-heads-up\config.json` on Windows). Missing file means all defaults.

```json
{
  "triggers":        { "stop": true, "notification": true },
  "skipWhenFocused": true,
  "throttleSeconds": 2,
  "media":  { "enabled": true },
  "sound":  { "enabled": true, "file": "" },
  "focus":  { "enabled": true },
  "toast":  { "enabled": true },
  "ntfy":   { "enabled": false, "server": "https://ntfy.sh", "topic": "", "token": "" }
}
```

- `sound.file` empty → bundled sound.
- `ntfy.token` may come from `HEADS_UP_NTFY_TOKEN` instead; the env var wins.
- `ntfy.enabled` with an empty `topic` is invalid: ntfy is skipped and a warning is logged.
- Unknown fields and invalid values: the field falls back to its default, a warning is logged, `doctor` reports it.
- docs/config.md tells users to pick a long random topic, since anyone who knows a public ntfy topic can read it.

## State and concurrency

State dir: `os.UserCacheDir()/claude-heads-up/`.

- `state.json`: `{ "ownerSession": "...", "pausedAt": "<RFC3339>", "media": [MediaSession...] }`. At most one record, because media is global.
- `throttle.json`: last alert time per session ID; entries older than 1 hour are pruned on write.
- Lock: `state.lock` created with exclusive-create. Give up after 1 s and skip the step. A lock file older than 10 s is stale and removed.
- A state record older than 6 hours is stale and deleted on read.
- If a second session alerts while a record exists, its pause finds nothing playing and the record keeps its original owner.
- All writes go to a temp file followed by rename, so a crash never leaves half-written JSON.

## Error handling

- Hook commands always exit 0 and write nothing to stdout or stderr.
- `main` recovers panics and logs them.
- Step timeouts: media 5 s, ntfy 3 s, others 2 s. A failed or timed-out step does not stop later steps.
- Log: `os.UserCacheDir()/claude-heads-up/heads-up.log`, rotated at 1 MB, one backup kept. `doctor` prints the path.
- `doctor` and `test` are interactive and do report errors with non-zero exit codes.

## Distribution

- `main` holds source only.
- `release.yml` runs GoReleaser on a `v*` tag: builds windows/amd64, windows/arm64, darwin/amd64, darwin/arm64, linux/amd64, linux/arm64; publishes a GitHub release; commits the plugin files plus `dist/` binaries to the `release` branch.
- `marketplace.json` points users at the `release` branch, so no download happens at runtime.

Install for users:

```
/plugin marketplace add ibbybuilds/claude-heads-up
/plugin install claude-heads-up
```

## Testing

- Unit tests (any OS): `engine` with fake platform, notifier, store and clock, covering ownership rules, throttle, focus skip, `ErrUnsupported` skips, step failure isolation; table tests for `config`, `state`, `hookinput`; `ntfy` against `httptest.Server`.
- Windows integration tests behind the `integration` build tag, run manually on a desktop session.
- `docs/manual-test.md`: YouTube in Brave and Chrome, Instagram web reels, Spotify desktop, Windows Terminal, VS Code, Claude desktop app, two concurrent sessions.
- CI: `go vet`, `golangci-lint`, `go test ./...` on windows-latest, macos-latest and ubuntu-latest.

## Risks to check early in implementation

- How Claude Code runs hook commands on Windows (Git Bash vs `cmd`). This decides whether `bin/heads-up` alone is enough or `heads-up.cmd` is needed. Verify before writing the launchers.
- Whether the Claude desktop app's Code tab runs plugin hooks the same way as the CLI.
- Whether Instagram web reels register with the Windows media session API in Brave and Chrome. If not, document it as a known limit; the ntfy push still covers phone use.
- Foreground lock behavior when the hook process is not the foreground process. Test the Alt-key workaround on Windows 11.
